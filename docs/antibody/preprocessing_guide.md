## 1. 预处理的整体目标

本文涵盖从 [生物组装体](bioassembly_guide.md) 解析完成到进入神经网络之前的全部处理步骤，涉及 [MSA](msa_guide.md) 和 [模板](template_guide.md) 特征的接入。

神经网络只接受数值张量（tensor），而蛋白质结构是一堆带有空间坐标的原子集合，MSA 是字符矩阵，模板是 PDB 结构文件。预处理的本质是**将异构的生物信息统一编码为形状一致、含义明确的张量**，并在这个过程中做三件事：

**① 净化**：过滤掉数据质量差的部分（坐标缺失、链碰撞、反常键合），防止模型从噪声中学习错误规律。

**② 压缩**：将大型结构（数千原子）裁剪为模型可以处理的片段，在信息量和计算量之间取得平衡。

**③ 编码**：将化学属性（氨基酸类型、元素、电荷、键合）和几何属性（坐标、方向、局部坐标系）转换为稠密向量，让模型能够以统一的方式"感知"不同类型的分子。

## 2. 两条预处理路径

Protenix 的预处理从根本上分为**训练路径**和**推理路径**，两者在起点、过滤强度和最终用途上都有差异：

```
训练路径                               推理路径
────────────────────                  ─────────────────────
mmCIF 文件（PDB 数据库）               用户提供的 JSON 输入
       ↓                                      ↓
  生物组装体解析                         结构/序列解析
       ↓                                      ↓
  严格质量过滤                          宽松（用户自负责任）
       ↓                                      ↓
  随机裁剪（子集）                        无裁剪（全结构）
       ↓                                      ↓
  坐标随机旋转/平移                       保持原始坐标
       ↓                                      ↓
  生成真值标签（ground truth）             无需标签
       ↓                                      ↓
──────────────────────────────────────────────────────
         两路在此汇合：Token 化 + 特征生成
──────────────────────────────────────────────────────
                      ↓
              模型输入特征字典
```

两路汇合点之后的处理逻辑完全一致，保证训练和推理看到的特征"语言"是相同的。

## 3. Tokenization：从原子到 Token 的抽象

### Token 是什么

Token 是 Protenix 模型操作的基本单位，介于原子和分子之间。它的定义取决于分子类型：

| 分子类型 | Token 粒度 | 代表原子 |
|---------|-----------|---------|
| 蛋白质标准残基 | 一个氨基酸残基 = 一个 token | Cα（alpha 碳） |
| RNA 标准碱基 | 一个核苷酸 = 一个 token | C1'（核糖 1 号碳） |
| DNA 标准碱基 | 一个核苷酸 = 一个 token | C1' |
| 配体 / 修饰残基 | 一个原子 = 一个 token | 原子本身 |
| 金属离子 | 一个原子 = 一个 token | 原子本身 |

**核心设计理念**：对于结构高度规律化的聚合物（蛋白质、核酸），以残基为单位比以原子为单位更高效——一个氨基酸平均约 7 个重原子，若以原子为单位，相同蛋白质的序列长度是以残基为单位的 7 倍，Transformer 的注意力计算量将放大 49 倍。对于化学结构多样的配体，则必须保持原子粒度，因为每个原子的化学属性都不同，无法进一步抽象。

### 多对一的映射关系

Token 化建立了一个从"多个原子"到"一个 token"的映射。每个 token 记录：
- 它代表的所有原子的索引列表
- 各原子的名称
- 代表原子（centre atom）的索引——这是 token 在空间中的"定位点"

这个映射关系在整个预处理流水线中持续维护：裁剪是在 token 级别做的，但坐标、掩码、键合等特征都需要通过这个映射还原到原子级别。**token 级索引和原子级索引是两套平行但相互关联的坐标系**，所有后续特征都必须保持这两套坐标系的一致性。

### Token 化为什么在过滤之后

Token 化发生在生物组装体解析完成之后，但早于裁剪。顺序的关键原因：
- 过滤需要在原子级别检查（如 Cα 距离、碰撞比例），需要完整的原子数组
- 裁剪以 token 为单位选取子集，必须先有 token 定义
- 特征生成依赖 token 的身份信息（残基类型等），必须在 token 化之后才能进行

## 4. 过滤：质量控制的逻辑层次

过滤分为两个阶段，分别在裁剪**前**和裁剪**后**各进行一次。逻辑是：先在全局结构上清理明显问题，裁剪后再对子集做局部验证。

### 第一轮过滤：全局清洗

**去除氢原子和氘原子**：氢原子在大多数 X 射线晶体学实验中无法分辨（分辨率不足），保留它们会引入大量位置不确定的坐标噪声。实验中有时用氘（D）替代氢做中子衍射实验，同样去除。

**去除水分子**：溶剂水（HOH/DOD）填充蛋白质表面和晶格空隙，是实验产物而非生物功能的一部分。保留水会给模型引入大量对预测无意义的原子，同时这些水的位置高度依赖结晶条件，泛化价值低。

**去除未知元素（X）**：原子类型标注为 X 的记录代表实验中无法确定元素的位置，以及某些模糊残基（如 ASX 可能是 ASP 或 ASN，GLX 可能是 GLU 或 GLN）。这类不确定信息输入模型只会产生噪声。

**去除结晶助剂**（非聚合物）：PDB 结构中常含有硫酸根（SO4）、甘油（GOL）等结晶过程使用的化学添加剂，与生物功能无关。若它们碰巧形成聚合物链（极罕见）则保留，否则过滤。

**链碰撞过滤**：若某条链有超过 30% 的原子与其他链的非共价原子距离小于 1.6 Å，说明这条链的坐标与邻近链在空间上严重重叠。这通常意味着晶体包装引入的人工接触，或坐标误差。此时：保留碰撞比例更低的那条链；若碰撞双方都很严重，则优先保留原子数更多的链（信息量更大）；始终优先保留"核心链"（Assembly 1 的链）。

**Cα 距离过滤**：蛋白质主链中相邻残基的 Cα-Cα 距离物理上不超过约 4 Å（肽键键长约 3.8 Å），若某对相邻残基的距离超过 10 Å，说明序列中有未解析的大段缺失，链已经"断裂"。这类断链的序列信息与坐标信息不对应，对模型有误导。

**全未知链过滤**：若一条聚合物链的所有残基都标注为未知（UNK），说明序列信息完全缺失，这条链对模型没有任何序列层面的监督信号。

### 第二轮过滤：裁剪后局部验证

裁剪后得到的子集可能因为截取边界的关系，产生一些在全局结构中不存在的问题（例如：全局中有 5 条链，但裁剪后这个子集中某条链只剩 2 个残基）。因此需要在裁剪后重新检查：残基是否太少、链内碰撞是否依然存在、是否有孤立的零原子 token。

## 5. 裁剪：让大结构变成可训练的片段

### 为什么需要裁剪

Transformer 的注意力机制计算量随序列长度**二次方**增长。一个大型蛋白质复合物可能有 5000 个 token，在 GPU 上全量处理需要海量显存，训练时几乎不可行。Protenix 将每个训练样本裁剪到最多 384 个 token（典型值），将计算量控制在可接受范围内。

另一个考量是训练信号的密度：若每个样本都包含整个大型复合物，模型在每一步更新时接触的信息过于稀疏。裁剪出局部片段反而让每步更新的信号更聚焦、梯度更有效。

### 三种裁剪策略及其逻辑

**策略一：连续裁剪（Contiguous Cropping）**

沿序列顺序，从随机起点截取连续的 token 子集。逻辑上类似于"随机从蛋白质序列里切出一段"。

适合学习的内容：序列相邻残基之间的局部结构规律、二级结构元素（α 螺旋、β 折叠）内部的规律、单链蛋白质的整体折叠。

局限：不擅长学习链间接口——两条链的接触区域在序列上是不连续的，纯连续裁剪很可能把接口"切散"。

**策略二：空间裁剪（Spatial Cropping）**

随机选取一个"中心 token"，将三维空间中距中心 15 Å 以内的所有 token 纳入样本。逻辑上是"在蛋白质的某个局部区域内切出一个球形子集"。

适合学习的内容：局部三维接触网络、配体结合口袋、链间接触面。空间裁剪天然地把"物理接近"的原子聚集在一起，包括来自不同链的原子。

局限：在蛋白质表面稀疏区域，可能裁剪出原子很少的样本，信息量不足。

**策略三：空间接口裁剪（Spatial Interface Cropping）**

与空间裁剪类似，但中心点被强制选在两条链的接触面（interface）附近。

适合学习的内容：链间相互作用的精细模式，如氢键网络、疏水核心、静电互补。对于预测蛋白质复合物（如抗体-抗原结合）特别重要。

**采样权重**：三种策略不等概率采样，连续裁剪权重较低（约 20%），两种空间裁剪权重较高（各约 40%）。这反映了 Protenix 的优先级——复合物接口和局部三维结构的预测比纯序列模式更重要，也更难学。

### 裁剪对 MSA 和模板的影响

裁剪是在 token 级别执行的，对应的 MSA 列（每个 token 对应 MSA 的一列）和模板坐标（每个 token 对应模板的一个残基位置）也同步截取到同样的 token 子集。这保证了序列信息、进化信息、模板信息、坐标信息在同一套 token 索引下保持一致对齐。

## 6. Token 级特征：序列与身份信息

裁剪之后，对保留下来的每个 token 生成一组描述其"身份"的特征：

### 残基类型编码（restype）

这是最核心的序列特征，将化学类型编码为离散整数（再做 one-hot 展开）：
- 蛋白质 20 种标准氨基酸：各占一个 ID
- 未知氨基酸（UNK）：1 个 ID
- RNA 4 种标准碱基（A/C/G/U）：各占一个 ID
- RNA 未知碱基（N）：1 个 ID
- DNA 4 种标准碱基（A/C/G/T）：各占一个 ID
- DNA 未知碱基（N）：1 个 ID
- gap（对齐缺口）：1 个 ID
- 配体原子：按元素类型编码

共 32 类，涵盖所有可能出现的 token 类型。统一的 32 类编码使模型能以相同的方式处理蛋白质、RNA、DNA 和配体 token，避免了为每种分子类型设计独立网络的复杂性。

### 位置与归属信息

每个 token 携带多个"身份坐标"，共同定义它"属于谁、在哪里"：

**residue_index**：在整个样本中的全局残基编号，从 0 连续递增，跨链不中断。这个编号让模型感知相对位置——两个 token 的 residue_index 差值反映它们在序列上的距离。

**asym_id**：链的整数编号，对应 mmCIF 中的 `label_asym_id`（但编码为整数）。同一条链内的所有 token 共享相同 asym_id，不同链的 asym_id 不同。让模型知道"这个 token 属于第几条链"。

**entity_id**：实体编号。同一种蛋白质序列（不论出现几次）的所有 token 共享相同 entity_id。例如同二聚体蛋白的两条链具有不同 asym_id 但相同 entity_id。让模型知道"这个 token 属于哪种分子"。

**sym_id**：对称拷贝编号。同一实体的第一个拷贝为 0，第二个拷贝为 1，以此类推。与 entity_id 结合，模型可以识别"这是这种分子的第几个副本"。

这四个 ID 共同构成一个层次化的身份体系：`entity_id` → 识别分子种类；`sym_id` → 识别哪个副本；`asym_id` → 识别物理链；`residue_index` → 识别在链内的位置。

## 7. 原子级特征：空间与物理属性

Token 级特征描述"是什么"，原子级特征描述"在哪里、长什么样"。

### 参考坐标（ref_pos）

每个原子有一个三维坐标向量 (x, y, z)，单位是埃（Å）。来源有两种情况：
- **已解析原子**：直接使用实验测定的坐标
- **未解析原子**（缺失或低置信度）：坐标设为零，并通过掩码标记为无效

坐标的特殊处理见第 12 节（数据增强）——训练时会对坐标进行随机旋转和平移。

### 参考掩码（ref_mask）

布尔值，1 表示该原子的坐标是真实测量值，0 表示坐标是占位零（未解析）。掩码的存在让模型能够区分"我知道这个原子在 (2.3, 4.1, -0.8) 处"和"这个原子存在但我不知道它在哪里"——这是完全不同的信息，不加区分会严重误导模型。

### 元素编码（ref_element）

每个原子的化学元素种类，以 128 维 one-hot 向量编码（元素周期表有约 118 种元素，留有余量）。元素决定了原子的基本物理化学属性：原子半径、电负性、成键倾向等。即使在同一种氨基酸内，碳原子和氮原子的行为也截然不同，元素编码让模型能区分它们。

### 形式电荷（ref_charge）

整数值，表示原子的形式电荷（如赖氨酸侧链氮在生理 pH 下带 +1 电荷，谷氨酸侧链氧带 -1 电荷）。电荷影响静电相互作用，是判断残基间能否形成盐桥的关键信息。

### 原子名称字符编码（ref_atom_name_chars）

原子名称（如 "CA"、"OG1"、"NZ"）以字符的 ASCII 码序列编码。这个特征看起来奇怪——为什么不直接用 one-hot 编码原子名称？原因是原子名称空间庞大（几百种），而配体的原子名称可能是完全新颖的（在训练集中从未出现过）。字符级编码有更好的泛化性：模型可以通过字符组合理解命名规律，而无需见过每一种可能的原子名称。

### 参考空间 UID（ref_space_uid）

整数值，将每个原子归组到它所属的残基。同一个残基的所有原子共享相同的 ref_space_uid。这个 ID 在坐标中心化（减去每组的均值）和原子到 token 的映射中被频繁使用。

## 8. 局部坐标系（Frame）：方向感的来源

### 为什么需要局部坐标系

原子坐标是全局坐标系下的绝对位置，但模型需要学习的是相对几何关系。更重要的是，模型的预测也需要输出结构——如果模型直接输出绝对坐标，那么对同一个蛋白质的不同朝向（旋转/平移后），模型就需要输出完全不同的数字，学习难度极大。

解决方案是为每个 token 建立一个**局部坐标系（frame）**，后续的结构预测以局部坐标系为参考，而不是全局坐标系。局部坐标系本身由 3 个原子的坐标定义，是**可旋转平移的**——全局旋转蛋白质，所有局部坐标系也同步旋转，但残基内的相对关系不变。

### 各分子类型的 Frame 定义

**蛋白质**：用主链三个原子 N（氮）、CA（alpha 碳）、C（羰基碳）定义局部坐标系。这三个原子构成肽键平面，是蛋白质主链最稳定、最具代表性的几何结构。选它们的另一个原因是它们在几乎所有蛋白质残基中都有实验坐标（除非残基完全缺失），保证了 frame 的可靠性。

**RNA/DNA**：用核糖环的三个碳原子 C1'、C3'、C4' 定义局部坐标系。核糖环是核苷酸的骨架结构，这三个原子同样在绝大多数核苷酸中有可靠坐标。

**配体和非标准残基**：没有固定的骨架原子，使用另一种策略——从该 token 的所有原子中，基于参考构象（CCD 提供的理想几何）找出最近的 3 个原子，用它们定义局部坐标系。

### Frame 有效性验证

并非所有 token 都能构建有效的 frame。以下情况下 frame 无效（`has_frame = 0`）：

- 可用原子不足 3 个（如只有孤立的金属离子）
- 3 个原子共线：若三点构成的角度小于 25° 或大于 155°，说明它们几乎在一条线上，无法定义平面，坐标系退化

frame 无效的 token 依然参与序列和特征处理，只是在需要坐标系的结构预测模块中被屏蔽（通过 `has_frame` 掩码）。

## 9. 键合特征：拓扑连接的表达

分子的三维结构不仅由坐标决定，还由原子间的化学键决定——键合限制了哪些原子可以相对运动。Protenix 将键合信息编码在一个 **token 级别的邻接矩阵**中。

### 什么键被编码，什么不被编码

**不编码**：聚合物主链内的骨架键（蛋白质肽键、核酸磷酸骨架）。原因是这些键的存在可以从序列信息中隐式推导——相邻的氨基酸残基必然有肽键相连，模型已经通过 residue_index 知道了序列连续性，不需要再显式告诉它"第 5 个残基和第 6 个残基之间有键"。

**编码**：聚合物与配体之间的共价键，以及配体内部的键合关系。这些键无法从序列信息推导，必须显式给出。例如金属离子与蛋白质残基的配位键、辅因子与蛋白质的共价连接。

**编码范围**：训练时使用距离阈值（< 2.4 Å）检测原子间是否成键，这基于共价键长度的经验值（大多数共价键键长在 1.2～1.9 Å 之间）。

### 键合矩阵的形状与语义

token 级键合矩阵的维度是 `(N_token, N_token)`，元素为 1 表示两个 token 之间存在共价连接，0 表示无连接。矩阵是对称的（A 连 B 则 B 也连 A），对角线为 0（token 不自连）。

这个稀疏矩阵让模型知道分子内的共价拓扑，有助于预测刚性片段的相对取向，以及金属配位构型。

## 10. 掩码体系：告诉模型哪些信息可信

Protenix 使用了一套精细的掩码体系，在不同的任务/评估场景下激活不同的原子子集。

### 为什么需要多种掩码

不同类型的预测（整体结构、局部置信度、距离图）关注的原子不同：
- 预测整体结构质量时，不必为每个侧链原子单独评估
- 预测距离图时，只需要代表每个残基的"代表原子"
- 评估配体结合口袋时，只需要配体周围的原子

定义多套掩码，让模型在不同计算模块中只处理相关的原子子集，避免不相关原子引入噪声，也提高计算效率。

### 主要掩码类型

**坐标掩码（ref_mask）**：标记哪些原子有实验确定的坐标。这是最基础的掩码，影响几乎所有后续操作。

**distogram 代表原子掩码**：每个 token 中用于计算残基间距离图的代表原子。蛋白质用 Cβ（GLY 用 Cα），RNA/DNA 用 C1'，配体用任意原子。这个掩码确保距离图计算时对每个 token 取唯一代表点。

**pLDDT 代表原子掩码**：局部距离差测试（pLDDT，一种局部预测质量指标）计算时使用的原子。通常选主链原子，因为主链的位置预测比侧链更稳定，更具代表性。

**PAE 代表原子掩码**：预测对准误差（PAE，衡量两个 token 之间相对位置预测质量）计算时的代表原子。

**修饰残基掩码（modified_res_mask）**：标记非标准残基（如被化学修饰的氨基酸）。在某些评估和损失函数中需要对这类残基做特殊处理。

## 11. MSA 与模板特征的接入

MSA 和模板特征（分别在 [MSA 完全指南](msa_guide.md) 和 [模板完全指南](template_guide.md) 中详细介绍）在特征生成阶段**并行注入**，与结构特征最终合并进同一个输入字典。

### MSA 特征的接入方式

MSA 特征是 **token 级别**的特征：MSA 矩阵的每一列对应一个 token（残基），每一行对应一条同源序列。因此 MSA 矩阵的形状是 `(序列数, token 数)`。

裁剪发生后，MSA 也被同步裁剪到相同的 token 子集，保持 token 维度与结构特征的一致性。来自不同链的 MSA 按链顺序在 token 维度拼接——链 A 的 token 在前，链 B 的 token 在后，MSA 未覆盖的 token 位置填充 gap。

若某条链没有 MSA（如配体），则为这条链的 token 创建一个"假 MSA"：只有一行，内容是该 token 的 restype——退化为纯序列信息，没有进化深度。

### 模板特征的接入方式

模板特征也是 token 级别的，但额外增加了一个"模板维度"：形状是 `(模板数, token 数, ...)`。每个模板独立对每个 token 提供坐标和几何信息。

同样地，裁剪后模板特征也被截取到相同的 token 子集。若某条链没有模板（如 RNA 配体），则创建全零的"假模板"填充，`has_frame` 掩码全为 0。

### 数据可用性的层次

Protenix 设计了优雅的降级机制：
- 最完整情形：有 MSA + 有模板 + 有完整坐标
- 无 MSA：用单序列假 MSA 替代，进化信息为零
- 无模板：用全零假模板替代，模板特征被掩码屏蔽
- 坐标部分缺失：缺失原子的掩码为 0，模型知道这些坐标不可信

这种设计确保模型在训练时能够处理各种数据完整性等级，推理时也能对信息不完整的输入给出有意义的预测（尽管精度会下降）。

## 12. 数据增强：让模型学会泛化

### 坐标随机旋转与平移

这是最重要的数据增强操作，**只在训练时执行**：

对每个参考空间单元（ref_space_uid，即每个残基）中的所有原子坐标，先减去中心（平均坐标），再应用一个均匀采样的随机旋转矩阵（来自 SO(3) 群），最后加上随机平移。

这个操作的核心目的是**旋转不变性训练**：蛋白质在空间中的朝向是任意的，但其结构性质不应随朝向改变。如果不做旋转增强，模型可能学习到"北偏东方向通常是螺旋"这类无意义的绝对方向偏好。随机旋转强迫模型只能依赖相对几何关系，而非全局方向。

重要细节：旋转是以**残基为单位**独立应用的，而非对整个蛋白质做统一旋转。这意味着增强后的坐标并不构成一个物理上有意义的三维结构——不同残基的坐标系是独立随机旋转的，彼此之间的相对位置被打乱了。这种"故意打乱全局结构"的设计反而更好：模型输入中的参考坐标不代表真实三维结构，模型被强迫不依赖参考坐标中的全局信息，只依赖 ref_element、ref_charge、ref_atom_name_chars 等纯化学属性——而这正是模型应该关注的。

### 配体原子名称混淆（可选）

将配体原子的名称替换为通用占位符（如 "C1"、"C2"、"N1"），隐去实际的化学命名。目的是测试模型在不知道配体原子具体身份时的预测能力，防止模型"作弊"依赖原子名称中的化学隐含信息。训练时可选，推理时通常不启用。

### 分子顺序随机打乱（可选）

随机打乱样本中各分子的排列顺序（调整 asym_id、entity_id、sym_id 的分配）。目的是消除数据准备过程中可能引入的位置偏差——若某类分子总是排在第一条链，模型可能学到"第一条链往往是某种类型"的虚假规律。

### 对称副本编号打乱（可选）

对于同二聚体等具有对称拷贝的复合物，随机决定哪个拷贝的 sym_id 为 0、哪个为 1。目的与分子顺序打乱类似：消除"第一个拷贝总是某种特定朝向"的偏差。

## 13. 操作顺序及其逻辑依赖

预处理的步骤顺序不是任意的，每一步都依赖前一步的结果。以下是完整的操作顺序和关键依赖关系：

```
Step 1: 解析生物组装体（mmCIF → AtomArray）
         ↓
         确立了原子集合和原子级注释
         ↓
Step 2: Token 化（AtomArray → TokenArray）
         ↓
         建立了原子→token 映射，确立了 token 粒度
         ↓
Step 3: 第一轮过滤（全局质量过滤）
         ↓  ← 依赖原子级信息（Cα 距离、碰撞检测）
         ↓  ← 过滤后 AtomArray 变小，TokenArray 同步更新
         ↓
Step 4: 采样索引选择（选择训练聚焦的链/接口）
         ↓
         确定了核心链，为裁剪提供"优先保留"信息
         ↓
Step 5: 裁剪（从整体 token 集合中选取子集）
         ↓  ← 依赖 token 化结果
         ↓  ← 依赖过滤后的 AtomArray
         ↓
Step 6: 第二轮过滤（对裁剪子集的局部质量过滤）
         ↓
Step 7: 生成 Token 级特征
         ↓  ← restype, residue_index, asym_id, entity_id, sym_id
         ↓  ← 依赖 token 化和裁剪结果
         ↓
Step 8: 生成原子级特征
         ↓  ← ref_pos, ref_mask, ref_element, ref_charge, ref_atom_name_chars
         ↓  ← 依赖 AtomArray 的坐标和原子属性
         ↓
Step 9: 构建局部坐标系（Frame）
         ↓  ← 依赖原子坐标和原子名称（已生成的原子特征）
         ↓
Step 10: 生成键合特征
          ↓  ← token_bonds, bond_mask
          ↓  ← 依赖 token 化结果和原子坐标
          ↓
Step 11: 加载并对齐 MSA 特征
          ↓  ← 依赖 token 子集（裁剪结果）以确定要保留哪些列
          ↓
Step 12: 加载并对齐模板特征
          ↓  ← 依赖 token 子集
          ↓
Step 13: 坐标增强（训练时：旋转 + 平移；推理时：跳过）
          ↓  ← 依赖原子坐标（Step 8 的结果）
          ↓
Step 14: 类型转换（Python numpy → torch Tensor，正确 dtype）
          ↓
Step 15: 组装最终输入字典
          ↓
        进入神经网络
```

关键依赖总结：
- Token 化必须在裁剪之前（裁剪以 token 为单位）
- 过滤必须在特征生成之前（特征基于过滤后的原子集合）
- MSA/模板接入必须在裁剪之后（需要知道哪些 token 被保留）
- 坐标增强必须在 Frame 生成之前或之后分别考虑（Frame 由坐标定义，若增强后坐标改变，需在增强后重新计算 Frame）

## 14. 训练 vs 推理的预处理差异

| 环节 | 训练 | 推理 |
|------|------|------|
| **数据来源** | PDB mmCIF 文件（预处理好的数据集） | 用户 JSON（结构/序列/MSA 路径） |
| **质量过滤** | 严格（所有过滤规则全部启用） | 宽松（用户自负责任） |
| **裁剪** | 是（随机三种策略之一） | 否（使用全结构；可选连续裁剪）|
| **坐标增强** | 是（随机旋转 + 平移） | 否（保持原始坐标） |
| **ground truth 标签** | 生成（原子真值坐标 + 评估掩码） | 不生成 |
| **分子顺序** | 可随机打乱 | 固定（用户输入顺序） |
| **模板日期过滤** | 严格（早于查询结构 60 天） | 固定截止日期（2021-09-30） |
| **循环次数（recycling）** | 随机采样（1 到最大值之间） | 固定（通常 4 次） |
| **噪声注入** | 有（对输入坐标加噪声，模拟不完整信息） | 无 |

### Recycling 机制的特殊性

Protenix 采用**迭代精化（recycling）**机制：模型不是一次性给出最终预测，而是将上一轮的预测结果（不完美的坐标）作为下一轮的输入一部分，反复精化。

**训练时**：循环次数随机采样，强迫模型在任意轮次都能给出合理的预测（即使输入坐标很不准确）。这种随机循环次数相当于对模型的"抗噪声能力"做了直接的训练。

**推理时**：固定 4 次循环，模型的输出逐步收敛——第 1 轮给出粗略结构，第 2 轮在第 1 轮基础上修正，以此类推。4 次通常足以让结构质量达到饱和。

## 15. 最终输入字典的全貌

所有预处理步骤完成后，最终组装成一个字典，送入神经网络。字典中各特征的维度以 `N_token`（token 数）、`N_atom`（原子数）、`N_msa`（MSA 序列数）、`N_template`（模板数）为基准：

**Token 级特征**（形状含 `N_token`）：
- `token_index`：token 序号，`(N_token,)`
- `residue_index`：全局残基编号，`(N_token,)`
- `asym_id`：链整数 ID，`(N_token,)`
- `entity_id`：实体整数 ID，`(N_token,)`
- `sym_id`：对称副本编号，`(N_token,)`
- `restype`：残基类型 32 类编码，`(N_token,)`
- `token_bonds`：token 间共价键矩阵，`(N_token, N_token)`

**原子级特征**（形状含 `N_atom`）：
- `ref_pos`：原子坐标，`(N_atom, 3)`
- `ref_mask`：坐标有效掩码，`(N_atom,)`
- `ref_element`：元素 128 维编码，`(N_atom, 128)`
- `ref_charge`：形式电荷，`(N_atom,)`
- `ref_atom_name_chars`：原子名称字符编码，`(N_atom, 4)`
- `ref_space_uid`：残基归组 ID，`(N_atom,)`
- `atom_to_token_idx`：原子→token 映射，`(N_atom,)`
- `frame_atom_index`：frame 三原子索引，`(N_token, 3)`
- `has_frame`：frame 有效标志，`(N_token,)`

**分子类型掩码**：
- `is_protein`, `is_rna`, `is_dna`, `is_ligand`：各 `(N_atom,)`

**MSA 特征**（形状含 `N_msa`）：
- `msa`：对齐矩阵，`(N_msa, N_token)`
- `has_deletion`：gap 标志，`(N_msa, N_token)`
- `deletion_value`：gap 长度，`(N_msa, N_token)`
- `profile`：位置权重矩阵，`(N_token, 32)`
- `deletion_mean`：平均 gap 长度，`(N_token,)`
- `prot_paired_num_alignments`, `rna_unpaired_num_alignments` 等深度计数

**模板特征**（形状含 `N_template`）：
- `template_restype`：模板残基类型，`(N_template, N_token)`
- `template_all_atom_positions`：原子坐标，`(N_template, N_token, 37, 3)`
- `template_all_atom_mask`：原子掩码，`(N_template, N_token, 37)`
- `template_distogram`：距离图，`(N_template, N_token, N_token, 39)`
- `template_backbone_frame_mask`：主链 frame 掩码，`(N_template, N_token, N_token)`

**评估掩码**（多种用途）：
- `pae_rep_atom_mask`, `plddt_m_rep_atom_mask`, `distogram_rep_atom_mask`：各 `(N_atom,)`

**元信息**：
- `resolution`：实验分辨率（埃），标量
- `is_distillation`：是否蒸馏数据，标量

**训练专有的标签**：
- `coordinate`：真值原子坐标，`(N_atom, 3)`
- `coordinate_mask`：哪些原子有真值，`(N_atom,)`
- `chain_1_mask`, `chain_2_mask`：接口评估用链掩码

整个字典通常包含约 40～60 个键，所有形状都以 `N_token` 或 `N_atom` 为基准，确保任意大小的蛋白质结构都能用同一套代码处理。

## 附录：关键概念速查

| 概念 | 含义 |
|------|------|
| **Token** | 模型操作的基本单位；蛋白质/核酸为一个残基，配体/离子为一个原子 |
| **Centre Atom** | 每个 token 的代表原子；蛋白质用 Cα，RNA/DNA 用 C1'，配体用原子本身 |
| **ref_space_uid** | 将同一残基的所有原子归为同一组的整数标识 |
| **Frame（局部坐标系）** | 由 3 个原子定义的局部参考坐标系，使结构特征对全局旋转/平移不变 |
| **残基 index 四元组** | `(asym_id, entity_id, sym_id, residue_index)` 共同唯一定位一个 token |
| **Recycling（迭代精化）** | 将上一轮预测坐标作为下一轮输入，多次循环逐步收敛 |
| **ATOM37** | 37 种可能原子名称的统一表示；密集原子（24 种）是其压缩版本 |
| **Distogram** | 残基对距离的 39 区间离散化表示，完全平移旋转不变 |
| **连续裁剪** | 沿序列截取连续 token 段，适合学习链内局部结构 |
| **空间裁剪** | 以某 token 为中心取半径内所有 token，适合学习三维局部环境 |
| **接口裁剪** | 空间裁剪的特例，中心点固定在链间接触面，聚焦接口学习 |
| **降级机制** | MSA/模板/坐标任一缺失时用假数据（全零/单序列）填充，系统不崩溃 |
