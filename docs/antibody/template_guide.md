## 1. 模板是什么，为什么存在

### 直觉类比

假设你要预测一栋陌生建筑的内部布局。方法一：从城市里所有建筑的特征统计规律中推断（类比 MSA）。方法二：找到一栋风格相似、已经可以进入参观的建筑作为参照（类比模板）。

两种方法都有价值，但参照建筑能提供的是**直接的空间信息**——这面墙的高度、那个门的位置——而不只是"城市里大多数建筑有几层楼"这样的统计。

模板（template）就是这个"可以参照的已知建筑"：它是蛋白质数据库（PDB）中已被实验解析的三维结构，与目标蛋白质有序列相似性，因此其空间构型可以作为预测目标蛋白质结构的直接参考。

### 模板的生物学基础

结构生物学中有一条核心经验规律：**序列相似的蛋白质往往折叠成相似的结构**。这条规律的成立是因为，进化过程中蛋白质序列允许随时间变化，但结构（即功能）必须维持——自然选择保护的是结构，而非序列。

这意味着：
- 两个蛋白质序列相似度仅 30%，仍可能具有极为相近的三维折叠
- 已知结构的蛋白质可以作为"结构模板"，指导未知结构的预测
- 序列相似度越高，模板的参考价值越大；但即使相似度较低，整体折叠拓扑仍可能保守

对于结构预测模型而言，模板提供的是**直接的空间先验**：告诉模型"在类似的序列中，这些残基大约处于这样的三维位置"，而不需要模型完全从序列信息从头推导。

## 2. 模板与 MSA 的根本区别

两者经常被并列提及，但承担的是完全不同的信息角色，有必要先厘清：

| 维度 | MSA（多序列比对） | 模板（Template） |
|------|----------------|----------------|
| **信息类型** | 进化统计信息 | 三维空间坐标 |
| **内容** | 数百至数千条同源序列 | 1～4 个已知三维结构 |
| **表达形式** | 氨基酸字母矩阵 | 原子 (x, y, z) 坐标 |
| **告诉模型什么** | 哪些位置共进化（暗示空间接触） | 这些位置在空间中实际在哪里 |
| **搜索依据** | 序列相似性（在序列数据库中） | 序列相似性（在 PDB 结构数据库中） |
| **数量** | 序列越多越好 | 通常取最多 4 个 |

MSA 提供的是**隐式的**结构约束：通过统计共进化信号，让模型自己推断哪些残基在空间上接近。模板提供的是**显式的**空间约束：直接给出坐标，模型可以直接参考。

**两者的协同关系**：MSA 说"根据进化历史，位置 A 和位置 B 经常协变，说明它们可能相互作用"；模板说"在结构相似的蛋白质中，A 和 B 确实仅相距 4 Å，且沿特定方向接触"。前者提供统计推断，后者提供空间验证。

## 3. 模板搜索：用 MSA 找结构

### 为什么用 MSA 来找模板，而不是直接用序列？

一个关键设计选择：Protenix 的模板搜索不是直接拿查询序列去 PDB 里比对，而是**先从 MSA 构建序列谱（Profile），再用谱搜索 PDB**。

原因在于：单条序列只能找到与自己高度相似的模板；而序列谱综合了数百条同源序列的统计特征，能识别更远的进化关系。一个蛋白质家族中不同成员的序列可能差异很大，但都折叠成同一种结构——谱能够覆盖这个家族的整体特征，发现那些"序列差异大但结构保守"的模板。

### 搜索工具：hmmsearch 与 HMM 谱

搜索工具使用的是 HMMER 套件中的 `hmmsearch`。关于 MSA 的详细介绍请参阅 [MSA 完全指南](msa_guide.md)。HMMER（Hidden Markov Model 搜索）的核心逻辑是：

1. 把输入的 MSA（来自 `pairing.a3m` 和 `non_pairing.a3m`）统计成一个 HMM 谱——每个位置用一个概率分布描述"哪种氨基酸出现在这里的概率"以及"这个位置发生插入/缺失的概率"
2. 用这个谱扫描 PDB 序列数据库（`pdb_seqres`），计算每条 PDB 序列与谱的匹配概率
3. 按概率（`sum_probs`）从高到低排列，得到一批候选命中

搜索结果同样以 A3M 格式保存，命名为 `hmmsearch.a3m`，与配对/非配对 MSA 文件并排存储在同一目录下。

### 搜索结果的本质

`hmmsearch.a3m` 中的每一条序列对应 PDB 中的一个蛋白质链，其描述行包含该链的 PDB ID、链标识符、序列起止位置，以及 HMMER 打出的匹配置信度。这些候选条目被称为**模板命中（template hits）**，是后续所有处理的起点。

## 4. 模板命中解析：从文本到结构化数据

### 命中的完整信息

每个模板命中被解析为一个结构化记录，包含：

- **身份标识**：PDB ID + 链名（如 `4kxt_A` 表示 4kxt 结构的 A 链）
- **搜索排名**：在结果列表中的位置（第几名）
- **置信度分数**：`sum_probs`，HMMER 打出的匹配概率，反映模板与查询序列的相似程度
- **对齐列数**：查询序列与命中序列之间实际对齐的残基数量
- **双向位置映射**：
  - 查询序列每个位置对应命中序列的哪个位置
  - 命中序列每个位置对应查询序列的哪个位置
  - `-1` 表示该位置在对方中是 gap（插入或缺失）

### 位置映射为何至关重要

模板的原子坐标是按**模板自身的序列顺序**排列的，而我们需要的是按**查询序列顺序**排列的坐标。位置映射就是这两套顺序之间的"翻译字典"。

举例说明：查询序列第 5 个残基映射到模板的第 7 个残基，则从模板提取坐标时，查询位置 5 的坐标来自模板位置 7；若某个查询位置无对应模板位置（gap），该位置的坐标留空（填零，并在掩码中标记为无效）。

### 解析的健壮性问题

PDB 数据库中的序列描述行格式并不总是标准的。有些条目缺少 `length:` 字段，有些用 tab 分隔而非空格，有些甚至把实际序列放在本该是数字的位置。

Protenix 的设计选择是**容错跳过**而非中止：对无法解析描述行的命中，直接记录一条警告日志并跳过，继续处理下一个候选。这避免了因为少数格式异常的条目导致整个结构被丢弃。

## 5. 预过滤：廉价筛选的逻辑

在进行昂贵的 mmCIF 文件解析之前，Protenix 先用四条廉价规则快速淘汰明显无用的候选：

### 规则一：对齐比例 ≥ 10%

`aligned_columns / query_length >= 0.1`

若对齐区域不足查询序列的 10%，意味着这个模板只覆盖了很小一部分查询，提供不了有效的整体结构参考。即便坐标是对的，对大多数查询残基也无法提供指导。

### 规则二：非近似重复

若命中序列是查询序列的大片段（覆盖超过 95%），则拒绝。这种情况下模板和查询几乎是同一个蛋白质的不同记录，用它作为模板没有意义——不提供新的信息，反而是一种循环论证。

### 规则三：最短长度 ≥ 10 个残基

命中序列（去掉 gap 后的有效残基）至少要有 10 个。少于 10 个残基的片段太短，既不可靠也无实际参考价值。

### 规则四：日期隔离

模板的 PDB 发布日期必须早于查询结构的发布日期（训练时要求至少提前 60 天）。这是防止数据泄露的核心机制——详见第 12 节。

### 预过滤的工程意义

这四条规则全部只需要读取命中的文本元数据（无需访问任何 mmCIF 文件），执行代价极低。而后续的 mmCIF 加载、序列对齐、坐标提取等操作每个都需要 I/O 和计算。通过预过滤将大量候选在早期淘汰，可以显著减少后续处理量。

## 6. 坐标提取：对齐是关键

通过预过滤的命中，接下来需要从实际的 PDB mmCIF 文件中提取三维坐标。这一步的核心难题是**序列对齐**，而且需要做两次对齐。

### 第一次对齐：hmmsearch 已完成

`hmmsearch` 搜索时已经建立了查询序列与命中序列之间的对齐（体现在 `TemplateHit` 的位置映射中）。然而，hmmsearch 使用的命中序列来自 PDB 序列数据库（`pdb_seqres.fasta`），它是文本形式的序列记录，不总是与 mmCIF 文件中记录的序列完全一致。

原因包括：
- 数据库版本不同步（序列数据库和 mmCIF 文件更新时间不一致）
- mmCIF 中的序列可能包含修饰残基的特殊标注
- 某些链的序列在数据库中被截断或拼接

### 第二次对齐：Kalign 重比对

因此，Protenix 不直接信任第一次对齐，而是用 **Kalign**（一个多序列比对工具）将查询序列与从 mmCIF 文件中读取的**实际结构序列**重新对齐。这次对齐才是最终用于提取坐标的依据。

**逻辑重点**：最终位置映射的建立——查询的第 i 个残基对应模板 mmCIF 中的哪个残基——完全依赖第二次对齐的结果。这个映射是提取坐标的"地图"。

### 从 mmCIF 读取的内容

解析 mmCIF 文件时，提取两类信息：

**头部信息（Header）**：分辨率、发布日期、实验方法（X 射线、冷冻电镜、NMR 等）。发布日期用于日期过滤，分辨率用于评估数据质量。

**原子坐标（Atom Site）**：每个已解析残基的每个原子的 (x, y, z) 坐标，以及 B 因子（原子位置的不确定性）。未被实验解析的残基（如柔性环区）在 mmCIF 中通常有序列记录但无坐标，被标记为缺失（`is_missing=True`）。

### 坐标提取的最终形状

将第二次对齐的映射应用到提取的坐标上，结果是一个按查询序列长度索引的坐标数组：

- 有对应模板残基且该残基有坐标 → 填入实际 (x, y, z) 值，掩码为有效
- 有对应模板残基但该残基缺失坐标 → 填零，掩码为无效
- 无对应模板残基（gap 位置） → 填零，掩码为无效

## 7. ATOM37：原子坐标的统一表示

### 每个蛋白质残基有多少个原子？

不同氨基酸的原子数量差异很大：甘氨酸（GLY）只有 4 个重原子，色氨酸（TRP）有 14 个。如果直接按实际原子数组织坐标，每个残基的数组长度就不同，无法形成规则的张量。

### ATOM37 的设计逻辑

Protenix 采用 **ATOM37** 标准：定义 37 种可能出现的原子名称（涵盖所有 20 种标准氨基酸的所有原子），每个残基统一用一个 37 维的坐标数组表示，配合一个 37 维的掩码（mask）数组指示哪些原子实际存在。

```
每个残基 = 37 × (x, y, z) 坐标 + 37 位掩码
总形状 = (残基数, 37, 3) 坐标 + (残基数, 37) 掩码
```

37 种原子包括主链原子（N, CA, C, O）和所有可能的侧链原子（CB, CG, CG1, CG2, OG, OG1, SG...）。对于实际不含某种原子的残基，对应坐标为零，掩码为 0。

这种"补零+掩码"的方法将可变长度的原子集合变为固定形状的张量，使得批处理和并行计算成为可能。

### 特殊情况处理

**硒代甲硫氨酸（MSE）→ 甲硫氨酸（MET）**：MSE 是实验室常用的甲硫氨酸替代物（便于 X 射线解析），其硫原子被硒取代，命名为 SE 而非 SD。Protenix 在提取坐标时将 MSE 的 SE 原子重命名为 SD，使其与标准甲硫氨酸的原子命名一致。

**精氨酸（ARG）对称性修正**：精氨酸胍基中有两个对称的 NH 原子（NH1 和 NH2），在某些 PDB 文件中标注可能是颠倒的。Protenix 通过与 CD 原子的距离比较来确认哪个是 NH1、哪个是 NH2，必要时进行交换，确保原子命名与实际几何位置一致。

## 8. 几何特征化：坐标如何变成可学习的输入

拥有原子坐标之后，仍需要进一步转换才能输入神经网络。核心问题是：**原始 (x, y, z) 坐标与全局参考系绑定，不同蛋白质的坐标不具有直接可比性。** 模型需要的是**旋转不变、平移不变**的几何特征。

### 步骤一：从 ATOM37 压缩为密集原子（Dense Atoms）

ATOM37 对多数残基来说很稀疏——GLY 只有 4 个有效原子，却占了 37 个位置，浪费了大量空间。Protenix 将每个残基压缩为一个**密集原子表示**，每种氨基酸只保留其实际拥有的原子（最多 24 个），并按氨基酸类型专属的顺序排列。

压缩之后，坐标形状从 `(残基数, 37, 3)` 变为 `(残基数, 24, 3)`，信息密度更高，且对齐了每种氨基酸的实际原子布局。

### 步骤二：提取伪β碳位置（Pseudo-Beta）

每个残基需要一个"代表点"用于计算残基间距离。自然的选择是 **Cβ 碳**（beta 碳，侧链第一个碳原子），因为它的位置隐含了侧链指向的方向。

例外是甘氨酸（GLY）：它没有 Cβ，侧链只有一个氢原子。GLY 用 **Cα 碳**（alpha 碳）代替。

这个用于计算的"代表点"称为**伪β碳（pseudo-beta）**，形成一个每个残基一个三维点的数组：形状 `(残基数, 3)`，配合一个掩码 `(残基数,)` 表示该点是否有效。

### 步骤三：距离图（Distogram）

将所有残基对之间的伪β碳距离计算出来，然后**离散化为 39 个区间**（bins）：

- 最小区间起点：3.25 Å（小于此值说明两个残基极近，可能是直接成键）
- 最大区间终点：50.75 Å（大于此值说明两个残基相距很远，几乎无相互作用）
- 区间边界不等距，近距离范围的分辨率更高

每对残基 (i, j) 的距离落入某个区间，用 one-hot 编码（39 维向量）表示属于哪个区间。

**结果形状**：`(残基数, 残基数, 39)`，每个元素是一个 39 维 one-hot 向量。

这个表示完全**不依赖全局坐标系**——它只记录残基对之间的相对距离，平移和旋转蛋白质不改变任何距离值。这正是旋转不变性的体现。

**为什么离散化而不用连续距离？**一方面，离散化相当于对噪声做了平滑处理（精确距离受实验误差影响，区间归属更稳健）；另一方面，one-hot 编码更容易被线性层处理，避免了模型对连续值的非线性拟合负担。

### 步骤四：单位向量（Unit Vectors）

距离图只告诉了模型"两个残基相距多远"，但没有告诉模型"它们相对于彼此处于什么方向"。方向信息对于判断二级结构（α 螺旋、β 折叠）和空间朝向至关重要。

Protenix 在**以每个残基为原点的局部坐标系**中，计算其他所有残基的相对方向向量，并归一化为单位向量：

1. 以残基 i 的主链原子（C、CA、N）构建一个局部参考坐标系——以 CA 为原点，C-CA 方向为 x 轴，N-CA 方向辅助确定 y 轴，z 轴由叉乘得到
2. 将残基 j 的 CA 坐标变换到残基 i 的局部坐标系中
3. 计算方向向量，归一化为单位长度（3 维）

**结果形状**：`(残基数, 残基数, 3)`

局部坐标系的设计使得这个特征**对全局旋转不变**——无论蛋白质在空间中如何旋转，每个残基在自身局部系中看到的其他残基方向是相同的。

### 步骤五：掩码体系

不是所有残基都有完整的坐标信息。Protenix 维护两类二维掩码：

**伪β碳掩码**：`pseudo_beta_mask_2d[i,j] = (i 的伪β有效) AND (j 的伪β有效)`。无效对在 distogram 中应被忽略。

**主链帧掩码**：`backbone_frame_mask_2d[i,j] = (i 有完整主链) AND (j 有完整主链)`。无效对在 unit vector 中应被忽略。

这两个掩码与特征张量配套传给模型，让模型知道哪些几何信息是可信的，哪些是填充的零值（需要忽略）。

## 9. 多模板集成：为什么要同时用多个

### 为什么不只用最好的那个？

直觉上，既然模板按置信度排序，取第一名不就够了？实际上有几个原因支持同时使用多个（Protenix 最多用 4 个）：

**① 蛋白质构象多样性**：同一蛋白质家族在不同物种、不同条件下可能折叠成略有差异的构象，不同模板捕捉了不同的构象变体。单一模板可能偏向某一构象，多模板集成提供了更均衡的参考。

**② 局部区域的互补覆盖**：排名第一的模板可能与查询序列在某个区域对齐很好，在另一个区域对齐差或坐标缺失；第二、三名模板可能恰好在那个区域有很好的覆盖。多模板能覆盖查询序列的不同片段。

**③ 减少系统性偏差**：单个模板的实验误差、晶体包装效应或特定物种偏好会带来系统性偏差。多模板平均能抵消部分偏差。

### 收集与排序逻辑

模板的选取遵循以下流程：

1. 对所有通过预过滤的命中，按 `sum_probs`（HMMER 置信度）降序排列
2. 按命中序列去重（避免 PDB 中同一结构的不同版本重复出现）
3. **训练时随机打乱 Top-K**（而非固定取前 4 个）——这是一种数据增强，让模型在不同训练步骤中看到不同的模板组合，防止对特定模板排序的过拟合
4. 最终取最多 4 个

### 特征的堆叠

4 个模板各自独立地完成坐标提取和几何特征化，然后沿"模板维度"堆叠：

- distogram 形状：`(4, 残基数, 残基数, 39)`
- unit vectors 形状：`(4, 残基数, 残基数, 3)`
- atom positions 形状：`(4, 残基数, 24, 3)`

若实际找到的模板不足 4 个，用全零填充至 4 个，模型通过掩码知道哪些是真实模板、哪些是填充。

## 10. 模板在模型中的角色

### 不是直接"看坐标"

模板特征不是作为参考坐标直接附加到预测结构上，而是通过神经网络层**嵌入**到模型的内部表示中。

### 嵌入方式：配对表示（Pair Representation）

模型内部有一个核心数据结构——**配对表示（pair representation）**，是一个 `(残基数, 残基数, 通道数)` 的张量，记录每对残基之间的相互关系。

模板特征被融入配对表示的过程：

1. **特征拼接**：对每个模板，将 distogram（39 维）、pseudo-beta 掩码（1 维）、氨基酸类型 one-hot（32 维，分别对 i 和 j 位置展开，共 64 维）、unit vector（3 维）、主链掩码（1 维）拼接在一起，形成每对残基的 108 维向量

2. **与查询配对表示融合**：用线性变换将 108 维模板向量与来自 MSA 的配对表示融合，形成一个"模板增强的"配对表示

3. **PairFormer 处理**：这个增强后的表示通过若干 transformer 层，模型在其中学习如何结合模板信息调整对残基间关系的理解

4. **跨模板平均**：对多个模板分别计算上述过程的输出，然后取平均——这正是多模板集成在模型层面的实现方式

### 氨基酸类型为什么展开为两个方向？

在拼接时，位置 i 的氨基酸类型和位置 j 的氨基酸类型分别编码，而非组合编码。原因是：模型需要分别学习"i 处是哪种氨基酸"和"j 处是哪种氨基酸"如何影响它们之间的距离关系，这两个条件是独立的。如果合并编码则组合数为 32×32=1024，数据稀疏；分别编码各用 32 维则更高效。

### 时间戳特征

每个模板还携带其 PDB 发布日期对应的 UTC 时间戳，作为模型的额外输入。这让模型能够隐式感知模板的"新旧程度"——较新的高分辨率结构可能更精确，较旧的结构可能有更多坐标缺失。

## 11. 边界情况与容错设计

### 找不到任何模板

当没有命中通过过滤时，模板特征全部填充为零，模板数量为 0。模型在没有模板的情况下仍然可以正常运行，此时结构预测完全依赖 MSA 和序列信息。这种情况常见于：
- 序列家族很新，还没有被实验解析结构的近亲
- 查询序列是一种新型蛋白质折叠

### 坐标部分缺失

低分辨率结构、NMR 结构、以及具有柔性环区的结构，通常有部分残基坐标缺失。Protenix 的策略是：
- 缺失坐标的残基 → 对应掩码置 0
- 模型看到掩码为 0 时，该位置的几何特征被忽略
- 不会因为部分缺失而丢弃整个模板

### 过时 PDB ID（Obsolete）

PDB 数据库偶尔会将旧条目标记为过时（obsolete）并指向一个替代条目（如 `1ABC` → `3DEF`）。Protenix 维护一张过时 PDB ID 映射表，遇到过时 ID 时自动查询替代条目，避免因为 ID 失效导致模板加载失败。

### 重试机制

对于偶发的网络错误或文件损坏，Protenix 实现了重试机制：若加载模板失败，最多重试 10 次（每次随机选取不同的训练样本）。若重试耗尽仍然失败，系统抛出明确的 `RuntimeError` 并附带详细错误信息，而非让程序以不可预期的方式崩溃。

## 12. 训练 vs 推理：时间隔离的必要性

### 数据泄露问题

结构预测的评估标准是：模型能否预测出它**从未见过**的蛋白质结构。如果训练数据中的模板包含了"被预测蛋白质本身解析出来后"的相关结构，模型实际上是在"作弊"——它学到的不是预测能力，而是记忆。

### 训练时：60 天安全缓冲

训练期间，每个查询结构都有一个 PDB 发布日期。模板的发布日期必须比查询结构**至少提前 60 天**才允许使用。

60 天缓冲的逻辑：在同一个科学项目中，相关结构往往会接近同一时间发表（例如一个蛋白质家族的多个成员同一年解析）。60 天缓冲减少了"同期研究成果相互泄露"的风险。

### 推理时：固定截止日期

推理时使用固定的截止日期（`2021-09-30`），来自 PDB 在这个日期之前发布的所有结构都允许作为模板。这与训练时的动态截止不同：推理时没有"查询结构"的发布日期作为参照，只能用训练数据集的截止日期作为统一基准。

### ColabFold 场景的特殊性

当用户通过 ColabFold 工作流进行推理时，可以选择不做日期过滤（用户自行控制），因为用户输入的查询序列可能并不来自 PDB，没有 PDB 发布日期概念，强行限制反而会减少有用的模板。

## 13. 设计哲学总结

Protenix 的模板系统体现了几条贯穿始终的设计取向：

**① 先筛后算，廉价在前**：预过滤完全基于文本元数据，不涉及任何三维坐标；坐标提取是在通过文本筛选之后才进行的重操作。这种"廉价操作前置"的流水线设计极大地减少了不必要的 I/O 和计算。

**② 旋转不变性优先**：所有最终输入模型的几何特征（distogram、unit vectors）均基于相对关系或局部坐标系，对全局旋转和平移不变。这不是偶然的：全局坐标是无意义的，两个相同的蛋白质在空间中的不同朝向不应该产生不同的特征。

**③ 缺失即掩码，不填猜测**：坐标缺失、对齐 gap、模板不足——所有这些情况都用掩码标记，让模型明确知道哪些信息是真实的、哪些是占位符。不猜测缺失值，是避免引入系统性偏差的重要原则。

**④ 集成优于单一**：无论是多模板平均还是训练时的随机模板打乱，都体现了对集成思路的偏好——单一模板的偏差、噪声或特殊性，通过多模板集成得到均衡。

**⑤ 时间隔离是红线**：日期过滤不是可选的性能优化，而是确保模型评估有意义的基础条件。评估时如果允许使用"未来模板"，预测结果将是不可信的。60 天缓冲则是在防止泄露与保留有用模板之间的工程权衡。

**⑥ 模板是先验，不是答案**：模板特征通过嵌入融入配对表示，而非直接复制坐标。这让模型保留了**推理能力**——模板提供的是方向和约束，而不是最终答案。当查询序列与模板有差异时，模型需要学会"在模板基础上做合理修正"，而不是盲目复制。

## 附录：关键概念速查

| 概念 | 含义 |
|------|------|
| **模板命中（Template Hit）** | hmmsearch 搜索到的一个 PDB 结构条目，包含对齐信息和置信度分数 |
| **sum_probs** | HMMER 打出的模板与查询谱的匹配置信度，越高越相似 |
| **ATOM37** | 37 种可能原子名称的统一表示，配合掩码指示哪些原子实际存在 |
| **密集原子（Dense Atoms）** | 按氨基酸类型压缩的原子表示，每种氨基酸最多 24 个，比 ATOM37 更紧凑 |
| **伪β碳（Pseudo-Beta）** | 残基的代表点：Cβ 碳（GLY 用 Cα 代替） |
| **Distogram** | 残基对伪β碳距离的离散化表示，共 39 个距离区间 |
| **单位向量（Unit Vector）** | 在局部主链坐标系中，指向其他残基方向的归一化向量 |
| **主链帧（Backbone Frame）** | 以 C、CA、N 主链原子构建的局部坐标系，用于计算方向特征 |
| **配对表示（Pair Representation）** | 模型内部记录每对残基关系的核心张量，模板特征通过它进入模型 |
| **时间截止（Date Cutoff）** | 允许使用的模板最晚发布日期，防止训练时的数据泄露 |
| **Kalign** | 多序列比对工具，用于查询序列与模板 mmCIF 序列的重新对齐 |
| **Obsolete PDB** | PDB 数据库中被标记为过时的条目，需映射到替代条目 |
| **hmmsearch** | HMMER 套件中用于用序列谱搜索数据库的工具 |
| **pdb_seqres** | 包含 PDB 所有蛋白质链序列的数据库，模板搜索的目标 |
