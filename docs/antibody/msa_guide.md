## 1. MSA 是什么，为什么有用

### 直觉类比

想象你在学习一个陌生单词的含义，但没有字典。仅凭一个句子中的上下文，很难判断它的意思。但如果你有 500 个不同语境下包含这个单词的句子，通过观察它在各语境中与哪些词搭配、哪些位置可以替换成其他词，你就能推断出它的含义和功能。

MSA（Multiple Sequence Alignment，多序列比对）对蛋白质的作用正是如此：它把来自不同物种的**同源蛋白质序列**对齐排列，让模型从"500 个语境"中推断每个位置的功能和结构约束。

### 什么是 MSA

给定一条蛋白质序列（称为查询序列，query），MSA 在基因数据库中搜索与之同源的所有序列，将它们对齐成一个矩阵：

```
位置：   1   2   3   4   5   6   7   8   ...
人类：   M   V   L   S   E   G   E   W
老鼠：   M   V   L   S   E   A   E   W
鸡：     M   I   L   S   E   G   E   W
大肠杆菌：M   -   L   T   E   G   K   W
酵母：   L   V   V   S   D   G   E   F
```

每一行是一个物种的同源蛋白序列，`-` 表示该位置在该物种中缺失（gap）。

### MSA 能告诉我们什么

这个矩阵携带了极其丰富的信息：

**① 保守性（Conservation）**：某个位置在所有物种中都是同一种氨基酸，说明这个位置在进化过程中从未改变。在结构上，这往往意味着它是蛋白质功能的核心，或者结构必须维持该氨基酸才能折叠正确。

**② 共进化（Co-evolution）**：位置 A 总是和位置 B 一起变化——人类版本 (E, K)，细菌版本 (D, R)。这种相关性揭示了两个位置在三维空间中**物理接触**，只有彼此协调才能维持相互作用。MSA 把这种空间接触信息隐含在统计关系中。

**③ 允许的变化范围**：某个位置出现了 15 种不同氨基酸，说明这个位置对结构的约束很宽松；而某个位置只出现 2 种，说明约束很严格。

AlphaFold 系列模型（包括 Protenix 所基于的 AlphaFold 3 架构）通过 MSA 获取上述所有信息，而无需显式编码这些规则——模型自行从对齐矩阵中学习。

## 2. 进化信息：MSA 背后的核心逻辑

### 为什么进化能揭示结构？

蛋白质的三维结构在进化过程中比序列**保守得多**。两条蛋白质序列的相似度可能仅有 20%，但仍然折叠成几乎相同的三维结构。这是因为蛋白质结构承载功能，自然选择维持结构，但允许序列在"兼容同一结构"的范围内漂移。

因此，来自不同物种的同源序列本质上是对"哪些序列组合可以折叠成这种结构"的天然采样。把数百条这样的序列排在一起，你就得到了一个隐式的结构约束数据集。

### 共进化信号的逻辑

假设两个残基 A 和 B 在三维结构中直接接触，相互作用。当 A 发生突变（例如从 E→D，负电荷变小），为了维持相互作用，B 往往需要协调突变（例如 K→R，维持正电荷）。如果 A 不接触 B，它们的突变则是独立的，不会表现出统计关联。

MSA 中捕捉的"协变（co-variation）"正是这种信号。深度学习模型通过 attention 机制可以直接从 MSA 矩阵中提取这些成对的统计依赖，用于预测残基之间的空间距离。

### MSA 深度的重要性

MSA 越深（序列越多），统计信号越可靠。只有 10 条序列的 MSA，协变信号噪声极大；有 5000 条序列的 MSA，信号就相当清晰。这是为什么 Protenix 需要付出如此大的工程努力去搜索和组织 MSA 数据——更深的 MSA 直接等于更准确的预测。

## 3. A3M 格式：MSA 的存储方式

Protenix 使用 **A3M 格式**存储所有 MSA 数据（文件后缀 `.a3m`）。

A3M 是 FASTA 格式的扩展，专门为对齐序列设计。其核心规则只有一条：**插入的氨基酸用小写字母表示，对齐位置用大写字母或 `-` 表示。**

```
>query（查询序列）
MVLSEGEWqlvlh

>物种A（有插入）
MVLSEGEWqlvLH

>物种B（有缺失）
MV-SEGEWqlvlh

>物种C（插入更多）
MVLSEGEWqlvlhVWAK
```

大写字母与 query 的对应位置一一对应，小写字母是插入（不对应 query 的任何位置）。

这个设计非常重要：**处理时只保留大写字母（及 `-`），小写字母被单独统计为"删除计数"（deletion count）**，记录该对齐位置前有多少个插入氨基酸。这样，无论同源序列比 query 长多少，最终特征矩阵的列数始终等于 query 的长度。

## 4. Protenix 的 MSA 来源体系

Protenix 的 MSA 并不来自单一数据库，而是精心设计了一套**多源融合**体系：

### 蛋白质 MSA 的两类来源

**配对 MSA（pairing.a3m）**
- 来源：搜索 **UniRef100**（包含所有已知蛋白质序列的非冗余数据库）
- 特点：包含完整的物种分类学信息（每个序列头部带有物种 ID，格式如 `OX=9606` 代表人类）
- 用途：专门用于**多链蛋白质复合物**的跨链比对（见第 6 节）
- 规模：每条查询序列通常得到数百至数千条同源序列

**非配对 MSA（non_pairing.a3m）**
- 来源：UniRef90、环境序列库（宏基因组数据）等其他数据库
- 特点：序列更多，但分类学信息不完整或格式不标准
- 用途：增加单链 MSA 的深度和多样性
- 规模：可达数万条序列

**模板搜索结果（hmmsearch.a3m）**
- 来源：对 PDB 序列数据库（pdb_seqres）做 hmmsearch
- 特点：这些序列对应**已有三维结构**的蛋白质
- 用途：不作为 MSA 特征输入，而是用于**模板特征**（见第 10 节）

三类文件存储在同一目录下，索引方式是**整数序列 ID**（每个唯一蛋白质序列分配一个整数）：

```
mmcif_msa_template/
├── 0/
│   ├── pairing.a3m
│   ├── non_pairing.a3m
│   └── hmmsearch.a3m
├── 1/
│   ├── pairing.a3m
│   ├── non_pairing.a3m
│   └── hmmsearch.a3m
...
```

用整数 ID 而非序列本身作为目录名，既避免了文件系统对长文件名的限制，也方便通过 `seq_to_pdb_index.json` 这张映射表快速定位任意序列的 MSA 目录。

### RNA MSA 的独立体系

RNA 有完全独立的搜索流程和数据库：
- **Rfam**：RNA 家族数据库，收录经人工注释的 RNA 序列家族
- **RNAcentral**：综合 RNA 序列数据库
- **NT-RNA**：核苷酸数据库中的 RNA 子集

三个数据库的搜索结果合并去重后，保存为单一的 `rna_msa.a3m`。RNA 不区分配对/非配对，因为 RNA 复合物的共进化配对逻辑远比蛋白质复杂，当前实现不做跨链 RNA 配对。

## 5. 四步构建流程：从结构到特征

Protenix 的 MSA 数据准备分为四个顺序步骤，贯穿从原始结构文件到可训练特征的全过程：

### Step 1：提取唯一蛋白质序列

**输入**：一批 mmCIF 结构文件
**逻辑**：遍历所有结构，提取每个生物组装体中的蛋白质序列（来自 `_entity_poly.pdbx_seq_one_letter_code`）。跨结构中完全相同的序列只保留一份，并分配一个整数 ID。同时建立双向映射表：序列→ID、ID→序列，以及序列→(PDB ID, 实体 ID) 的多对多映射。
**输出**：`pdb_seq.fasta`（去重后的所有序列）+ 三张 JSON 映射表

**设计考量**：序列去重是关键的工程优化。实际 PDB 数据库中，大量蛋白质结构共享相同序列（同一蛋白质在不同条件下结晶），若不去重，同一条序列会被搜索几十次，浪费大量计算资源。

### Step 2：执行 MSA 搜索

**输入**：Step 1 输出的 FASTA 文件
**逻辑**：对每条唯一序列，调用序列搜索工具（jackhmmer 或 mmseqs2）在大型蛋白质数据库中查找同源序列。搜索本质上是一个迭代过程：先用原始序列搜索，再用搜索结果构建"序列谱（profile）"，再用谱搜索，重复几轮以发现更远的同源体。
**输出**：以整数 ID 命名的 A3M 文件（`0.a3m`, `1.a3m`, ...），存储在初始目录

**设计考量**：基于谱（profile）的搜索比逐对序列比较能发现更远的同源关系，覆盖更广的序列空间，获得更深的 MSA。这是为什么 Protenix 不用简单的 BLAST 而用 jackhmmer 或 mmseqs2 的原因。

### Step 3：追加分类学 ID

**输入**：Step 2 的原始 A3M 文件
**逻辑**：解析每条同源序列的描述行（header），提取或补充 NCBI 物种分类学 ID（taxid）。例如人类序列的 taxid 是 9606，大肠杆菌是 562。Protenix 支持两种格式的 header：UniRef 格式（`UniRef100_{hit}_taxid/`）和 UniProt 格式（`OX=TaxonomyID` 字段）。
**输出**：带有标准化分类学注释的 A3M 文件

**设计考量**：物种 ID 是 Step 4 中跨链配对的唯一依据。如果搜索结果缺少物种信息，就无法对多链复合物进行正确配对。这一步是整个多链 MSA 体系的基础。

### Step 4：拆分并组织

**输入**：Step 3 的带注释 A3M 文件
**逻辑**：对每条序列，将搜索到的所有 hits 按来源数据库拆分：UniRef100 的结果写入 `pairing.a3m`，其他来源写入 `non_pairing.a3m`。同时将之前用于模板搜索的 hmmsearch 结果（另外生成）放入同一目录。
**输出**：按整数 ID 组织的目录结构（`mmcif_msa_template/0/`, `mmcif_msa_template/1/`, ...）

**设计考量**：拆分的意义在于让后续流水线能对两种 MSA 实施不同的处理策略——配对 MSA 按物种精确配对，非配对 MSA 直接堆叠。若混在一起，物种信息不完整的序列会破坏配对逻辑。

## 6. 分类学配对：多链 MSA 的关键创新

这是 Protenix（继承自 AlphaFold 3）相比早期方法最重要的设计创新，专门针对**蛋白质复合物**的结构预测。

### 问题：单链 MSA 无法捕捉链间共进化

传统做法是对每条蛋白质链单独搜索 MSA，互不关联。对于预测单链结构（单体），这完全足够。但对于多链复合物，链与链之间的相互作用才是关键——两条链的接触面如何形成、哪些残基配对，取决于它们协同进化的历史。

如果链 A 和链 B 的 MSA 是完全独立的（序列来自不同物种，随机拼接），模型看到的"A 来自人类、B 来自细菌"这种组合在生物学上没有意义，提供不了有效的接口共进化信号。

### 解决方案：按物种对齐

Protenix 的思路是：在同一物种中，链 A 和链 B 的同源序列**很可能真实地相互作用**。把同一物种的两条序列配成一对，模型看到的是"这两个序列在自然界中协同进化、真实形成接口"，这才是有意义的共进化信号。

**配对逻辑步骤：**

**① 构建物种-序列映射**：对复合物中的每条链，从 `pairing.a3m` 中提取所有同源序列，按物种 ID 分组。例如链 A 有人类同源序列 5 条、大肠杆菌同源序列 3 条；链 B 有人类同源序列 8 条、酵母同源序列 4 条。

**② 筛选共现物种**：只有在**所有链中都出现**的物种才有配对价值。上例中若只有人类同时在链 A 和链 B 中出现，则只有人类的序列对用于配对。

**③ 排序与截断**：能覆盖更多链的物种优先排列；每个物种中保留的序列数有上限（约 600 条/物种），防止某个物种的序列过度代表。

**④ 构造配对矩阵**：每一行是一个物种的序列组合——链 A 的第 i 条序列与链 B 的对应序列并排拼接成一行。若某物种在某条链中无对应序列，该位置填充 gap。

**结果的形状**：原本每条链有独立的 MSA 矩阵（行=序列数，列=该链长度），配对后得到一个联合矩阵（行=共现物种数，列=所有链长度之和）。每一行代表一个跨物种、跨链的协同进化记录。

### 为什么这个逻辑有效

这个设计基于一个生物学前提：**在同一物种内相互作用的蛋白质，其接触面的氨基酸组合是共进化约束的结果**。通过强制配对同物种序列，Protenix 让模型能够学习"什么样的链 A 氨基酸组合能与什么样的链 B 氨基酸组合形成稳定接口"，而不是依赖噪声拼接。

这也是 Protenix 能预测蛋白质复合物结构（抗体-抗原、蛋白质-DNA、酶-配体）的重要基础之一。

## 7. 双流合并：配对 MSA 与非配对 MSA

Protenix 始终同时维护两个独立的 MSA 流，并在最后阶段合并：

### 两流的职责分工

**配对 MSA 流**（来自 pairing.a3m）
- 职责：提供跨链共进化信号
- 特性：序列数相对较少，但每条序列携带精确的物种信息
- 不去重：同一物种的多条序列都保留，因为它们代表不同个体内的变异，配对信息有独立价值
- 容量上限：约 4096 行

**非配对 MSA 流**（来自 non_pairing.a3m）
- 职责：提供单链进化多样性，补充配对 MSA 的深度
- 特性：序列数多，但物种信息不完整
- 主动去重：移除与配对 MSA 已有序列完全相同的条目（避免重复信息）
- 容量：填满配对 MSA 占用后的剩余空间（总上限约 16384 行）

### 合并的优先级逻辑

合并时，配对 MSA 始终排在最前面，非配对 MSA 追加在后。这个顺序不是随意的：模型的 attention 机制对序列位置敏感，将信息密度最高的配对序列放在前面，有助于模型优先关注最有价值的共进化信号。

当复合物中有多条链时，非配对部分的合并方式是**填充（padding）**：对于只在一条链上有 MSA 的序列，其他链对应位置填充全 gap。这样所有链的 MSA 行数对齐，可以统一输入模型。

### 深度追踪

最终特征中记录三个深度计数：蛋白质非配对深度、蛋白质配对深度、RNA 非配对深度。这些数字告诉模型"实际有多少条序列可用"，使模型能够根据 MSA 质量调整其预测置信度——对深度很浅的 MSA 持更保守的态度。

## 8. MSA 到特征向量的转换逻辑

原始 A3M 文本需要转换为数值张量才能输入神经网络。这个转换过程体现了若干重要的设计选择。

### 序列的整数编码

每个氨基酸字符映射为一个整数。对蛋白质，使用 22 类编码：20 种标准氨基酸各一个 ID、未知氨基酸（X）一个 ID、gap（-）一个 ID。RNA 使用 6 类编码（A/C/G/U/N/gap）。

小写字母（插入）不编码进主矩阵，而是转化为**删除矩阵（deletion matrix）**：记录每个对齐位置前方有多少个被插入的氨基酸。这样无论插入多少，主矩阵的列数始终固定为查询序列长度。

### 谱（Profile）的角色

除了原始 MSA 矩阵外，Protenix 还计算每个位置的**氨基酸频率分布**（称为 profile）。Profile 是一个 (序列长度 × 21) 的矩阵，每列是该位置上各氨基酸出现的频率向量。

Profile 的意义在于它是 MSA 的"摘要"：即使 MSA 有数千行，profile 把信息压缩成固定大小的矩阵，让模型无需处理可变数量的序列就能获得统计保守性信息。同时，删除均值（deletion mean，每个位置的平均插入数）作为第二个摘要特征，编码了插入/缺失的分布模式。

### 坐标对齐（Coordinate Mapping）

MSA 的序列来自外部数据库，其残基编号与 Protenix 内部的 token 体系（来自生物组装体解析）并不天然对应。必须建立从"MSA 残基位置"到"token 数组位置"的精确映射，才能保证每条特征正确对应到三维坐标。

这个映射通过比对查询序列（MSA 第一行）与生物组装体中的序列来建立。只有在 token 数组中被选中的残基才会保留对应的 MSA 列；未出现在 token 中的残基（如被过滤掉的残基）的 MSA 列被丢弃。

## 9. RNA 的特殊处理

RNA 的 MSA 处理逻辑与蛋白质有几处本质差异：

**① 不做跨链配对**：RNA 与蛋白质的共进化模式非常不同，当前 Protenix 不对 RNA 链做分类学配对，RNA 的 MSA 始终以非配对模式处理。

**② 独立的数据库体系**：蛋白质用 UniRef 系列，RNA 用 Rfam + RNAcentral + NT-RNA 三库联合搜索。RNA 数据库规模远小于蛋白质数据库，MSA 深度上限也相应调低（约 30000 行，而蛋白质是 16384 行，但实际 RNA MSA 通常比蛋白质浅很多）。

**③ 不同的搜索工具**：蛋白质用 jackhmmer/mmseqs2，RNA 用 nhmmer（HMMER 套件中专为核酸序列设计的工具）。核酸的碱基配对二级结构对 MSA 质量有特殊要求，nhmmer 能更好地处理这类约束。

**④ 编码方案不同**：RNA 只有 4 种碱基（A/C/G/U）加未知（N）和 gap，共 6 类编码，远比蛋白质的 22 类简单。

## 10. MSA 与模板搜索的协作关系

MSA 和模板搜索在 Protenix 中紧密协作，形成两个互补的信息来源（模板系统的完整介绍请参阅 [模板完全指南](template_guide.md)）：

### MSA 产生模板候选

模板搜索不是直接用查询序列去搜索，而是**先从 MSA 构建序列谱（HMM profile），再用谱搜索 PDB 序列数据库（pdb_seqres）**。这就是 hmmsearch 的名字来源——用 Hidden Markov Model（隐马尔可夫模型）做搜索。

用谱搜索比用单条序列搜索有显著优势：谱综合了数百条同源序列的统计信息，能发现更远的同源模板，包括序列相似度很低但结构相似的蛋白质。

### 模板提供结构先验

MSA 提供的是**序列层面**的进化信息（哪些氨基酸倾向于共同出现），而模板提供的是**结构层面**的先验（已知三维坐标）。两者分别从不同角度约束预测：
- MSA → 通过共进化隐式约束残基间距离
- 模板 → 通过已知坐标直接提供空间参考

当一条蛋白质序列有较好的模板（序列相似度 > 30%），模板特征往往是结构预测中最强的信号。当没有好的模板时，MSA 的共进化信号就承担了主要的约束作用。这也是为什么 Protenix 需要同时支持两个路径，而不是只用其中一个。

### 时间隔离（Data Leakage 防护）

训练时，模板日期过滤是防止数据泄露的关键机制：模板的 PDB 发布日期必须早于查询结构的发布日期，否则模型相当于"提前看到了答案"。MSA 因为只涉及序列而无坐标，不需要做日期过滤。

## 11. 训练 vs 推理：MSA 处理的差异

### 训练阶段

训练时，所有 MSA 都是**预计算并存储在磁盘**上的。数据加载时直接读取 `pairing.a3m`、`non_pairing.a3m`、`hmmsearch.a3m` 三个文件，经过配对-合并流水线（`FeatureAssemblyLine`），生成最终特征。

这个设计的工程考量是：MSA 搜索本身非常耗时（每条序列需要分钟级别），若在训练时动态搜索则不可行。预计算将搜索成本分摊到数据准备阶段，训练期间只做特征变换，效率大幅提高。

### 推理阶段

推理时，用户通过 JSON 输入文件提供 MSA 路径（或内联文本）。Protenix 支持两种方式：

**方式一：使用完整 MSA**（推荐，精度高）
用户自行运行 jackhmmer 或 colabfold_search，生成配对/非配对 A3M 文件，在 JSON 中指定 `pairedMsaPath` 和 `unpairedMsaPath`。

**方式二：使用 ColabFold MSA**（简便，精度略低）
ColabFold 使用 mmseqs2 进行快速近似搜索，速度比 jackhmmer 快约 10 倍，但原始输出中不含物种分类学信息，无法直接配对。Protenix 提供了 `colabfold_msa.py` 后处理脚本，通过给序列分配**伪分类学 ID**（pseudo taxonomy ID）来模拟配对所需的物种信息，代价是配对质量略低于真实分类学配对。

这个"伪 ID"方案本质上是一个工程妥协：ColabFold 搜索出来的序列，按其出现顺序或相似度排序，人为给相似序列分配相同的伪 ID，近似模拟"来自同一物种"的效果。对推理时效要求高的场景（药物设计、快速筛选），这种近似通常是可接受的。

## 12. 设计哲学总结

Protenix 的 MSA 系统体现了以下几条一贯的设计哲学：

**① 进化信息是结构信息**：MSA 不只是"序列的堆叠"，它是经过亿年进化筛选的结构约束数据集。系统的设计目标始终是最大化提取这种约束信息，而不只是凑够序列数量。

**② 多链需要联合处理**：传统单链 MSA 对单体足够，但蛋白质复合物的结构预测需要捕捉链间共进化。分类学配对是解决这一问题的核心机制，代价是更复杂的数据管理。

**③ 质量优先于数量**：配对 MSA 严格要求物种信息完整、来自 UniRef100；非配对 MSA 才是"广撒网"。前者控制配对信号的质量，后者补充深度。两者不可混淆。

**④ 预计算与在线处理的权衡**：搜索的计算成本与训练的频率决定了预计算是正确的工程选择。推理时支持多种 MSA 输入方式，用灵活性换取适应不同场景的能力。

**⑤ 序列、结构、进化三位一体**：MSA（进化）→ 模板（结构先验）→ 生物组装体（结构真值），三条信息流在数据管道中并行流动，在模型中汇合。没有哪条单独足够，三者缺一不可。

## 附录：关键概念速查

| 概念 | 定义 |
|------|------|
| **查询序列（Query）** | 我们要预测结构的目标蛋白质序列（MSA 第一行） |
| **同源序列（Homolog）** | 与查询序列有共同进化祖先的序列（来自不同物种） |
| **保守位置（Conserved）** | 在所有同源序列中几乎不变的氨基酸位置 |
| **共进化（Co-evolution）** | 两个位置的氨基酸类型在进化中协调变化，暗示空间接触 |
| **分类学 ID（Taxid）** | NCBI 为每个物种分配的唯一整数，用于识别序列来自哪个物种 |
| **UniRef100** | 包含所有已知蛋白质序列的非冗余数据库（最全） |
| **A3M 格式** | MSA 文件格式，小写字母表示插入，大写/gap 表示对齐位置 |
| **删除矩阵（Deletion Matrix）** | 记录每个对齐位置前有多少插入氨基酸的数值矩阵 |
| **谱（Profile / HMM Profile）** | 从 MSA 统计得到的每位置氨基酸频率矩阵，用于更灵敏的搜索 |
| **jackhmmer** | 基于 HMM 的迭代蛋白质序列搜索工具 |
| **nhmmer** | 专为核酸（RNA/DNA）序列搜索设计的 HMMER 工具 |
| **mmseqs2** | 高速近似序列搜索工具，ColabFold 使用 |
| **配对 MSA** | 包含物种信息、用于跨链配对的高质量 MSA |
| **非配对 MSA** | 物种信息不全、用于增加单链深度的 MSA |
| **MSA 深度** | MSA 中包含的序列条数，越深统计信号越可靠 |
